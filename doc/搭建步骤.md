# 搭建步骤

## 先说结论
不要先把前端界面全部写完。

这个项目更合理的起点是：
先定流程和接口，再搭后端最小骨架，最后让前端围绕接口去联调。

原因很简单：
- 这个项目的核心价值不在页面样式
- 核心在“检索、提取、总结、导出”这条链路
- 如果先猛写前端，后面接口一变，页面还要反复改

## 正确起手顺序
建议按下面顺序写。

1. 先定第一版范围
先锁死 MVP，不要一开始做太大。

第一版只做：
- 固定几个官方文档源
- 输入关键词
- 返回候选文档
- 提取正文
- AI 总结
- 导出 Markdown

第一版先不做：
- 全网搜索
- 百度搜索
- PDF/DOCX 导出
- 多轮对话
- 自动规划复杂任务

2. 先定义前后端数据流
先把这条链路写清楚：

用户输入关键词  
前端调用后端接口  
后端检索官方文档  
后端抓取并提取正文  
后端调用 AI 总结  
后端返回总结结果和文档列表  
前端展示结果并提供导出

如果这一步没定清楚，后面代码一定会乱。

3. 先定义接口，不要先写页面细节
前端和后端之间先约定数据结构。

第一版至少要有这些接口：
- `POST /api/search`
- `POST /api/summarize`
- `GET /api/report/:id`

接口先约定输入输出：
- 关键词怎么传
- 文档源怎么传
- 返回哪些字段
- 报错时返回什么

这一步比先写按钮和布局更重要。

4. 先搭后端最小骨架
后端先跑起来，再谈前端联调。

后端第一步不是写 AI。
后端第一步是把服务入口整理成真正的 Web 服务。

建议先完成：
- 一个服务入口文件
- 一个健康检查接口
- 一个假数据版 `search` 接口
- 基本错误处理

目标不是一开始就做真搜索。
目标是先让前端有东西可调。

5. 再做前端最小页面
前端第一版不要追求完整 UI。

先做最小闭环页面：
- 搜索输入框
- 文档源选择区
- 开始分析按钮
- 结果展示区
- 加载状态
- 错误提示

先让页面能成功调用后端假接口。
这比先做复杂样式有价值。

6. 先完成“假数据联调”
这是很关键的一步。

后端先返回固定数据。
前端先把这些固定数据渲染出来。

这样你可以先验证：
- 接口是否通
- 状态管理是否合理
- 组件拆分是否合适
- 页面交互是否顺

如果这一步都没走通，不要急着接真实抓取。

7. 再把后端假数据替换成真实检索
联调稳定后，再开始做真实逻辑。

建议顺序：
- 先做官方文档候选页检索
- 再做候选页筛选
- 再做正文提取
- 再做 AI 总结
- 最后做 Markdown 导出

不要反过来。
尤其不要一开始就做导出。

## 结合你当前项目的实际写法
你现在已经有：
- `web/`
- `server/`
- `doc/`

所以项目方向已经对了。

当前更合理的职责是：

### web
负责：
- 用户输入
- 调用接口
- 展示进度
- 展示结果

不负责：
- 抓取网页
- 提取正文
- 调用 AI 密钥

### server
负责：
- 提供 HTTP 接口
- 检索文档
- 提取正文
- 调用 AI
- 生成报告

### doc
负责：
- 记录需求
- 记录搭建步骤
- 记录后续迭代

## 推荐开发顺序
按这个顺序最稳：

1. 整理 `server` 目录
把旧 CLI 思路彻底切开。
后端主入口要变成 Web 服务入口。

2. 先写后端基础接口
先有：
- `GET /api/health`
- `POST /api/search`

哪怕先返回假数据也行。

3. 再改前端页面
前端先围绕接口做最小页面。
先不追求复杂视觉。

4. 前后端第一次联调
确认前端能调用后端并拿到数据。

5. 后端逐步替换成真实业务逻辑
从假搜索换成真实搜索。
从假总结换成真实 AI。

6. 最后再补体验层
包括：
- 加载态
- 失败提示
- 来源展示
- Markdown 导出

## 前端应该先写到什么程度
可以先写，但只能写到“可联调”的程度。

前端第一阶段只需要这些组件：
- `SearchForm`
- `ResultList`
- `SummaryPanel`

先让它们接收假数据。
不要一开始就做完整视觉稿。

## 后端应该先写到什么程度
后端第一阶段只要完成：
- 服务能启动
- 路由能访问
- 返回固定 JSON

先把“接口存在”这件事做出来。
不要一开始就陷入网页解析细节。

## 最适合你的开工点
如果你问“现在第一步到底写什么”，答案是：

先写后端最小接口骨架。

第一步就做两件事：
- 启动一个 Node Web 服务
- 提供一个返回假数据的 `POST /api/search`

然后马上回到前端，把这个接口接起来。

## 为什么不是先全做前端
因为这个项目不是普通展示页。

它的难点在后端流程：
- 搜索来源
- 内容提取
- AI 总结
- 文件导出

前端只是承载层。
所以前端可以早做，但不能先做完。

## 第一周建议目标
如果按学习项目节奏推进，第一阶段目标建议是：

1. 后端服务能启动
2. 前端页面能调用后端
3. `search` 接口先返回假数据
4. 页面能展示候选文档列表

做到这里，项目就算真正起步了。

## 第二阶段再做什么
第一阶段跑通后，再继续：

1. 接真实文档源
2. 做正文提取
3. 接 AI 总结
4. 做 Markdown 导出

## 一句话总结
这个项目前期最正确的起手，不是先堆前端页面，而是先把“后端接口骨架 + 前端最小联调页面”一起跑通。
