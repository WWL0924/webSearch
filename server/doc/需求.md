# 项目需求

项目目标：
用户输入技术问题或关键词后，系统在多个官方技术文档站点中检索相关页面，读取前 3 到 5 篇文档正文，调用 AI 生成总结，最后导出一份 Markdown 报告。

这个范围合理。
原因是它同时覆盖了前端交互、后端流程编排、网页内容提取、AI 接入、结果导出，学习价值够高，但实现成本还可控。

## 项目版本迭代说明


第一版不做：
- 全网搜索
- 百度检索
- 任意站点抓取
- 用户自定义抓取规则
- PDF 导出
- DOCX 导出
- 多轮对话式 Agent
- 自动规划和自动执行复杂任务

第一版只做：
- 固定 3 到 5 个官方技术文档源
- 关键词检索
- 候选页面筛选
- 正文提取
- AI 总结
- Markdown 报告导出

## 推荐项目名
可选名称：
- MyDocAgent
- TechDoc Agent
- Official Docs Summarizer

## MVP 功能范围

## 前端
- 输入关键词
- 选择文档源
- 点击开始分析
- 展示检索进度
- 展示命中的文档列表
- 展示 AI 总结结果
- 导出 Markdown 报告

## 后端
- 接收关键词
- 在官方文档源中检索
- 拉取网页内容
- 提取正文
- 标准化内容
- 调用 AI 总结
- 生成 Markdown 文档

## 文档源范围
第一版建议只支持以下站点中的 3 到 5 个：
- `react.dev`
- `vite.dev`
- `nodejs.org`
- `developer.mozilla.org`
- `typescriptlang.org`

不要一开始接太多站点。
先把少量站点做稳定。

## 核心流程
1. 用户输入关键词。
2. 后端在指定官方文档站点中检索候选页面。
3. 系统筛选出前 3 到 5 个真正相关的文档页。
4. 后端抓取页面并提取正文。
5. 后端整理正文内容并裁剪无关信息。
6. 调用 AI 生成总结。
7. 生成 Markdown 报告并返回下载。

## 模块拆分

## 1. 文档源配置模块
每个文档源至少配置：
- 站点名称
- 域名
- 搜索方式
- 是否允许抓取
- 正文提取规则
- 标题提取规则
- 需要忽略的区域

## 2. 检索模块
职责：
- 根据关键词搜索官方文档
- 返回候选页面标题和链接

控制范围：
- 第一版只支持站内检索
- 第一版只返回前 5 条结果

## 3. 候选页筛选模块
需要过滤掉：
- 首页
- 导航页
- 更新日志目录页
- 无正文的索引页
- 重复页面

目标：
只保留真正适合总结的内容页。

## 4. 正文提取模块
需要处理：
- 标题提取
- 正文区域提取
- 代码块保留
- 导航和页脚去除
- 侧边栏去除

输出统一结构：
- 标题
- URL
- 来源站点
- 正文文本
- 代码片段

## 5. AI 总结模块
输入：
- 3 到 5 篇文档的标准化内容

输出建议固定为：
- 问题结论
- 关键知识点
- 实现建议
- 注意事项
- 参考来源

注意：
不要把这个模块做成开放聊天。
第一版只做单次分析和总结。

## 6. 报告导出模块
第一版只导出：
- `Markdown`

报告建议包含：
- 查询关键词
- 分析时间
- 参考文档列表
- AI 总结结果
- 原文链接

## 非功能要求
- 单页抓取失败时不能让整个流程中断
- 页面请求需要有超时控制
- AI 总结失败时要返回错误提示
- 保留简单日志，方便调试和演示

## 技术实现建议

## 前端
- `React + Vite`

## 后端
- `Node.js`
- 提供简单接口给前端调用

## 关键能力
- 页面检索
- HTML 获取
- 正文提取
- AI API 调用
- Markdown 文件生成

## 开发顺序
1. 先完成文档源配置。
2. 再完成关键词检索。
3. 再完成候选页面筛选。
4. 再完成正文提取。
5. 再接入 AI 总结。
6. 最后补 Markdown 导出和前端展示。

## 简历表达重点
这个项目最终要突出下面几点：
- 做过一个可运行的 AI Agent 风格项目
- 能把外部知识源接入到 AI 流程中
- 能完成检索、提取、总结、导出这一整条链路
- 具备前后端联调能力

## 二期扩展
第一版做完后，再考虑这些增强项：
- 增加更多官方文档源
- 增加结果缓存
- 增加 PDF 或 DOCX 导出
- 增加引用片段高亮
- 增加多轮追问
