# Node 文件批处理 CLI

## 作用
这个技能用于操作和排查当前项目的本地 CLI，主要覆盖：
- 批量改名
- 批量移动
- 按后缀过滤
- 交互式分步输入

## 何时调用
当用户提出以下需求时调用：
- 需要正确运行 `fp` 命令
- 需要拼装改名表达式（含 `name`、`index`）
- 需要按后缀过滤（`all` 或指定扩展名）
- 需要排查 CLI 参数、路径校验、`npm link` 行为

## 当前参数顺序
`fp <fromDir> [toDir] [role] [targetExt]`

- `fromDir`：必填，源目录
- `toDir`：可选，目标目录，默认等于 `fromDir`
- `role`：可选，改名表达式，默认保持原名
- `targetExt`：可选，后缀过滤，默认 `all`

## 表达式上下文
在改名表达式中可用变量：
- `name`：不含后缀的文件名
- `index`：当前循环下标

示例：
- 保持原名：`"name"`
- 拼接序号：`"name + '_' + index"`
- 取首字符：`"name[0]"`

## 命令示例
- 原地改名（处理全部后缀）：
  `fp ./list ./list "name + '_' + index" all`
- 移动并改名（仅处理 txt）：
  `fp ./list ./list1 "name + '-moved-' + index" txt`
- 交互模式（缺参时逐步提问）：
  `fp`

## 常见坑位
- 表达式要加引号，例如：`"name + '_x_' + index"`
- `abc` 不加引号会被当变量，`eval` 会报错
- 源目录和目标目录必须存在且为文件夹

## 安全提示
- 当前实现使用 `eval(role)`，只执行可信表达式
- `fs.rename` 在跨目录时等价于“移动文件”

## 快速排障
1. `fp` 命令找不到：
   - 在项目根目录执行 `npm link`
2. 路径报错：
   - 检查路径是否存在且是否为目录
3. 表达式报错：
   - 打印 `role`，检查 shell 引号转义是否正确
